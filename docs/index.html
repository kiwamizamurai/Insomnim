Why Insomnim

It talks to macOS directly — not through caffeinate

Insomnim keeps macOS from idling to sleep — and, optionally, from dimming the display — for as long as it's running. Rather than spawning caffeinate as a subprocess, it calls IOPMAssertionCreateWithName / IOPMAssertionRelease directly. Both interfaces, CLI and menu bar, share one core: SessionController.

🛰️

No subprocess

Talks to IOKit Power Management directly through FFI — nothing shells out.

💾

Nothing on disk

No settings, cache, or logs are ever written. Nothing to clean up.

📡

Zero network

No telemetry, no update checks, no network access at runtime — ever.

One core, two interfaces

CLI or menu bar — pick whichever fits the moment

Both interfaces are driven by the same SessionController state machine, so behavior never drifts between them.

Under the hood

Built with intent, not shortcuts

Six decisions that shape how Insomnim behaves — and how it fails safely when something goes wrong.

01

Talks to IOKit directly

No caffeinate subprocess. The CLI alone doesn't even depend on the darwin package.

02

Ports and Adapters

SessionController only knows the InhibitorFactory / SleepLease ports — every macOS detail lives under platform/.

03

Safe cleanup

SleepLease.close() is idempotent; defer/finally release the assertion on every exit path, exceptions included.

04

Acquire-before-release

Reconfiguring while running acquires the new assertion first, so a failure leaves the old state untouched.

05

Multi-language UI

A dependency-free i18n module. Switching language in the GUI re-renders everything instantly, no restart.

06

Deterministic tests

17 unit tests driven by a fake inhibitor — no dependency on real IOKit or wall-clock time.

Get started

From zero to awake in three commands

Requires macOS on Apple Silicon, Homebrew, and the Xcode Command Line Tools.

install 
# Homebrew, then the repo
brew install nim
git clone https://github.com/kiwamizamurai/Insomnim.git
cd Insomnim
nimble test   # 17 unit tests
usage 
# Inhibit indefinitely, until Ctrl+C
insomnim

# 30 minutes, also preventing the display from sleeping
insomnim --timeout 1800 --display

# Only while rsync is running
insomnim -- rsync -av ./src/ backup:/data/

# Force Japanese output regardless of the system locale
insomnim --lang ja --help
build & package 
nimble release   # bin/insomnim        (CLI)
nimble gui       # bin/insomnim-gui   (GUI, fetches darwin)
nimble app       # dist/Insomnim.app  (bundled icon, ad-hoc signed)

--system-sleepAlso request PreventSystemSleep (subject to OS limits)

-- COMMAND ARGS...Inhibit only while COMMAND runs, return its exit code

Security & limitations

What it promises — and what it doesn't

🔒 Security & privacy

  • No network access, telemetry, or update checks at runtime
  • No admin privileges required; never touches system-wide power settings (pmset)
  • Power Management assertions are acquired and released per-process
  • No Keychain use; no settings or logs are ever persisted to disk

Limitations

  • macOS only — no Windows or Linux support
  • Sleep on lid-close is not guaranteed to be prevented
  • GUI settings, including language, are not persisted across restarts
  • No protection against multiple instances; CLI and GUI don't share state
  • Built for the local machine's architecture (arm64), not universal
